# Diabetes Prediction ML

A beginner-friendly Python project that explores the Pima Indians Diabetes
dataset, compares Logistic Regression with Random Forest, and provides a
command-line predictor and a Streamlit demonstration.

> **Medical disclaimer:** This project is for education and demonstration only.
> It is not a medical device and must not be used to diagnose, treat, or make
> healthcare decisions. The dataset and model have limitations and predictions
> can be wrong. Consult a qualified healthcare professional about health
> concerns.

missing, by running the same downloader before fitting.
The root `train.py` and `predict.py` files are small launchers; implementation
lives in `src/` so the same logic is shared by the CLI and web app.

## Requirements and installation

Use Python 3.10 or later. Open PowerShell in the project root and run:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks activation, use `.venv\Scripts\python.exe` in place of
`python` for the commands below.

## Get the real dataset

The project downloads the original 768-row Pima dataset from a public mirror
of the Kaggle/UCI dataset. It verifies the expected feature names and binary
target before saving anything; if the primary source is unavailable, it tries
a second public mirror. No synthetic data is generated.

Run:

```powershell
python download_data.py
```

The script creates `data/` as needed and saves the verified CSV to
`data/diabetes.csv`. If the file already exists, it validates it and does not
download or overwrite it. The expected columns are `Pregnancies`, `Glucose`,
`BloodPressure`, `SkinThickness`, `Insulin`, `BMI`,
`DiabetesPedigreeFunction`, `Age`, and `Outcome`. The Kaggle source page is
[Pima Indians Diabetes Database](https://www.kaggle.com/datasets/uciml/pima-indians-diabetes-database);
see [`data/README.md`](data/README.md) for dataset notes.

## Explore the data

Open `notebooks/diabetes_analysis.ipynb` in VS Code or Jupyter from the project
root, select the project's Python environment as the kernel, and run the cells.
The notebook uses Pandas, NumPy, and Matplotlib to review data shape, column
types, descriptive statistics, target balance, invalid zeros, distributions,
and correlations. It raises a clear error if the CSV is absent.

## Train and evaluate

From the project root:

```powershell
python train.py
```

The script:

1. Loads the CSV with Pandas, validates its columns and binary target, and
   reports a dataset overview and exploratory statistics.
2. Uses a domain-based transformer to interpret zero Glucose, BloodPressure,
   SkinThickness, Insulin, and BMI values as missing. Zero pregnancies remains
   valid.
3. Splits data into stratified training and test subsets. Median imputation
   and Logistic Regression scaling live inside Scikit-learn pipelines, so
   their learned values come only from the training portion of each fold.
4. Compares Logistic Regression and Random Forest using five-fold stratified
   cross-validation on the training set. The model with the highest mean
   training-fold ROC-AUC is selected.
5. Reports test accuracy, precision, recall, F1-score, ROC-AUC, and a confusion
   matrix for each model.
6. Saves the selected, complete pipeline to
   `models/diabetes_model.pkl`.

The test set is for final reporting, not model selection. Metrics are not
evidence of clinical safety or usefulness. If the CSV is missing, run `python download_data.py` first. Only the real
dataset described above is used for model training.

## Predict from the command line

After training, provide a value for each input:

```powershell
python predict.py --pregnancies 2 --glucose 120 --blood-pressure 70 --skin-thickness 25 --insulin 80 --bmi 28.5 --diabetes-pedigree-function 0.5 --age 32
```

The command prints the predicted class and the model's estimated probability
for class 1. Invalid zero measurements are handled by the same pipeline as
training; a zero pregnancy count is allowed.

## Run the Streamlit app

After installing dependencies and training the model:

```powershell
python -m streamlit run app.py
```

The app presents all eight input fields and displays the class estimate and
class-1 probability. A trained model must exist before predictions can be
made. The medical disclaimer is displayed in the app.

## GitHub: publish the project

The dataset and trained model are excluded from Git by `.gitignore`. This keeps
the separately downloaded data and generated binary artifact out of the
repository; collaborators should download the CSV and train their own model.

1. Create an empty repository on GitHub (for example,
   `Diabetes-Prediction-ML`).
2. In PowerShell, from this project directory, initialize and push the source:

   ```powershell
   git init
   git add README.md .gitignore requirements.txt app.py download_data.py train.py predict.py src notebooks data/README.md models/.gitkeep
   git status
   git commit -m "Build diabetes prediction ML project"
   git branch -M main
   git remote add origin https://github.com/YOUR-USERNAME/Diabetes-Prediction-ML.git
   git push -u origin main
   ```

3. Replace `YOUR-USERNAME` with your GitHub account name. Follow GitHub's
   authentication prompts; never put access tokens or passwords in source
   files or the remote URL.

If you intentionally choose to distribute a model, first verify the dataset
terms, model provenance, size, and safety requirements. A joblib/pickle model
can execute code when loaded, so only load artifacts from trusted sources.
Scikit-learn model files are not guaranteed to be compatible across versions.

## Key machine-learning ideas

- **Invalid zeros:** Some zero entries in the source dataset represent
  unrecorded medical measurements, not real measurements. They are converted
  to missing values. Pregnancy count is not converted because zero is
  meaningful.
- **Pipeline and leakage prevention:** The zero correction is a fixed
  domain-specific rule. The median imputer and scaler are fitted inside each
  cross-validation training fold and then applied to its validation fold.
  Final fitting uses the full training split; the held-out test split is not
  used to choose the winning model.
- **Models:** Logistic Regression is a linear baseline. Random Forest
  combines decision trees and can learn non-linear relationships.
- **Metrics:** Accuracy is the total share correct. Precision describes the
  share of positive predictions that are correct; recall describes the share
  of positive cases found. F1 balances precision and recall. ROC-AUC measures
  ranking quality over thresholds. The confusion matrix lists actual classes
  by predicted classes.

This repository is an educational example, not a validated clinical tool.
